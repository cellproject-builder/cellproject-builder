# Instalação e uso em outros dispositivos

A opção **Configurações → No seu dispositivo** instala o workspace quando o navegador disponibiliza o evento de instalação. Sem esse evento, a interface explica a instalação pelo menu; em iPhone/iPad, orienta abrir no Safari e usar Compartilhar → Adicionar à Tela de Início. O prompt só abre após clique. Aceitar o prompt não é registrado como instalação concluída: a aplicação aguarda a confirmação do navegador ou o modo standalone.

O manifesto usa `start_url`/`scope` `/`, display standalone e ícones PNG 192/512, maskable separado e apple-touch-icon de 180. São um símbolo neutro de estrutura de plano; não alteram o texto da marca no workspace. Os SVGs e `src/pwa/generateIcons.mjs` permitem reproduzir os arquivos.

O service worker é registrado **somente no build de produção**, em contexto seguro. Desenvolvimento/HMR e o bundle de chave local não entram no cache PWA. `npm run build` carimba o worker com hash dos assets e do HTML: novas versões podem ser detectadas pelo navegador. A atualização espera um clique em **Atualizar e reiniciar**, sem recarregar silenciosamente durante uma edição.

O cache contém o shell HTML obtido sem credenciais, manifesto, ícones e os assets públicos enumerados pelo build. Nunca intercepta `/api`, uploads, mídia do usuário fora dos caminhos de assets, requests com Authorization, métodos de escrita, query strings ou terceiros. Respostas privadas/no-store, redirecionadas e opacas não são armazenadas. Navegação usa a rede e só cai no shell público em falha; sua resposta não é gravada. Uma versão pública anterior é mantida durante a troca: uma aba antiga pode obter seu lazy chunk já armazenado nessa versão. Caminhos de assets ausentes da lista atual e do cache anterior passam à rede sem alteração da requisição e nunca são gravados.

Isso não implementa IA offline, pesquisa de imagens offline ou sincronização entre dispositivos. Os dados já pertencem ao armazenamento local deste navegador; instalar o aplicativo não os transfere para outro telefone/computador. O backup/importação existente continua sendo o mecanismo de portabilidade do workspace. IA, gateway e pesquisas precisam de conexão e servidor disponível. O shell em cache reduz dependência de rede após uma visita, sem promessa de todo fluxo offline.

Responsividade: o mapa preserva sua largura em tablet ao abrir detalhes/chat em sobreposição; smartphone conserva navegação por drawer, scroll do conteúdo, safe areas e alvos maiores nas escolhas de imagens. Não são adicionados novos cartões ao canvas para instalação.

Verificação dirigida: testes de evento único/erro/aceite versus conclusão, iOS, desenvolvimento sem SW, exclusões do cache, fallback sem gravar navegação, mensagem explícita de atualização, hash de release e dimensões reais dos PNGs. Instalação real em iOS/Android e ciclo de atualização entre dois deploys não foram exercitados em dispositivo nesta rodada. Referências de implementação: [instalação progressiva](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/How_to/Trigger_install_prompt) e [ciclo de service worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).
